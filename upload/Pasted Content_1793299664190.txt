What REA actually is (verified)
REA (Reverse Engineer Anything) — github.com/morluto/rea, MIT, TypeScript, shipped as rea-agents on npm. It's an MCP server + CLI that equips coding agents (Claude Code, Codex, Cursor, Gemini CLI) with 70+ constrained analysis tools plus "skills" that enforce an investigation methodology: decompile → understand → recreate.

Two design choices explain why it succeeds where generic agents failed you:

Constrained tools, not free-form browsing. The agent can't improvise. It gets disciplined primitives — page structure, script inspection, network observation, screenshots (and decompilers for binaries) — wrapped in an enforced methodology. No wandering, no hallucinated DOM dumps.
Evidence v2. Every finding is recorded deterministically with confidence, authority, limitations, and source locations — content-addressed, exportable/importable across sessions, with resumable checkpoints. Conclusions come with receipts.
For websites specifically — this is the part that matters for you: REA's browser observation attaches to a Chrome instance you already run (loopback CDP endpoint + explicitly approved origins) and is passive by design. It does not evaluate page JavaScript, does not navigate, click, or close anything, and it redacts sensitive values (never retains headers, bodies, cookies, storage, WebSocket payloads). It observes; it never acts. That is literally your "analysis only, no execution" requirement, enforced at the tool level rather than trusted to a prompt.
